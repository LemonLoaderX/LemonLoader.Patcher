**Breaking update:** Patcher 2.0 changes accepted Loader payloads, distribution
layout, cache locations and the Core integration API. Use it with the layout-9
payload in Loader **v0.7.4-android.1 or later**. Older Loader formats require their
matching historical tooling. The host still requires .NET 10.

## Breaking changes and migration

| Affected use | Change | Required migration |
| --- | --- | --- |
| Loader Release inputs | Layout 8, MonoVM and external crypto-helper DEX releases are rejected. | Supply a current layout-9 CoreCLR Release. Use the matching Android or Bionic archive and retain Release/hash, ZIP, ABI and completeness validation. |
| Download/install scripts | Each platform now has separate CLI and GUI archives instead of one combined package with shared tools. | Select `LemonLoader.Patcher.CLI-win-x64.zip`, `LemonLoader.Patcher.GUI-win-x64.zip`, `LemonLoader.Patcher.CLI-linux-x64.tar.gz` or `LemonLoader.Patcher.GUI-linux-x64.tar.gz`. The selected executable is at archive root. |
| Executable deployment | Each front end owns its adjacent `Tools/Il2CppInterop` and legal files; GUI native libraries remain adjacent. | Move the whole extracted archive. Update old `CLI/` or `GUI/` launch paths and do not copy only the executable or rely on a shared sibling Tools directory. |
| Download caches | Downloads use `.tools` beside the selected Patcher executable. Old output-adjacent caches are not consulted. | Use a writable Patcher directory. Move reusable Cpp2IL, UnityDependencies and runtime ZIP cache entries as described in [usage](https://github.com/LemonLoaderX/LemonLoader.Patcher/blob/v2.0.0/docs/USAGE.md#inputs); CLI and GUI installations have separate caches. |
| Interop reuse | Automatic Interop output caching is removed. | Generate for the exact game, export to a dedicated DLL directory, and pass it explicitly with `inject --interop` or `patch --interop` when reuse is intended. A generation manifest is not required for injection. |
| Core API integrations | Request types and pipeline responsibilities are reorganized under `LemonLoader.Patcher.Core`; generation and post-processing are composed separately. | Rebuild integrations against `PatchRequest.Generation`, `PatchRequest.PostProcessing`, `InteropPipeline` and `ApkProcessingPipeline`. See the [composition contract](https://github.com/LemonLoaderX/LemonLoader.Patcher/blob/v2.0.0/docs/WORKFLOW.md#composition-and-ownership). |
| Installed metadata consumers | Injection no longer writes or recomputes the retired revision/tree-hash/runtime-identity recipe. | Consume ordinary payload files and policy overrides under the current Loader contract. Do not require removed metadata in downstream installation scripts. |

## Updating workflows

The existing `patch` operation remains available. Standalone stages let scripts
avoid generation or injection when only one operation is needed:

```text
LemonLoader.Patcher.CLI generate-interop game.apk --output GameInterop
LemonLoader.Patcher.CLI inject game.apk --output patched.apk --release Loader.zip --interop GameInterop
LemonLoader.Patcher.CLI process-apk patched.apk --output aligned.apk --align
```

Use `.exe` on Windows and `./` when launching from the extracted directory.
Generation exports replace their destination transactionally; use a dedicated
directory. APK input and output must differ. Directory injection updates the
input directory in place. Start from an original game, preserve package/signing
identity for updates, and retain case-distinct APK entries when using external
unpack/repack tools.

Alignment and signing remain explicit, independent options; the last example
aligns only. Use `patch --help` and the [workflow guide](https://github.com/LemonLoaderX/LemonLoader.Patcher/blob/v2.0.0/docs/WORKFLOW.md) for the
complete option and signing contracts. No app installation is performed by Patcher.

## Changes included and limits

Directory injection uses an uncompressed temporary payload and extracts directly
into transaction staging, avoiding an extra overlay copy. Validation, cancellation
cleanup and rollback remain; distribution APK compression is unchanged.

The bundled Interop fork includes string Span handling and native proxy HFA fixes.
Existing generated DLLs are not rewritten; generate again when the game inputs or
required generator behavior change. Runtime-specific Loader limitations still
apply, and Linux GUI interaction remains a separate qualification boundary.
